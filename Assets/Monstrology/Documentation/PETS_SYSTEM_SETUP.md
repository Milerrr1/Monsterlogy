# Личные питомцы: настройка и интеграция

## Разделение данных

Система не изменяет назначение энциклопедии.

- `CreatureData` — вид существа: Хлебокот, Космокот, Гриболис.
- `CreatureInstance` — конкретный питомец игрока с уникальным ID, именем, уровнем, редкостью и характером.

Один открытый вид может соответствовать нескольким `CreatureInstance`. Счётчики энциклопедии по-прежнему хранятся отдельно в `GameManager`.

## Новые скрипты

- `CreatureInstance.cs` — сериализуемая модель питомца и enum `PetRarity`/`PersonalityType`.
- `CreatureCollectionManager.cs` — коллекция, любимчик, имя, опыт, уровни и сохранение.
- `PetsPanel.cs` — список питомцев и карточка выбранного экземпляра.
- `PetAdoptionDialog.cs` — предложение добавить питомца при первом открытии вида.

В `CreatureInstance.cs` также подготовлены структуры:

- `AccessorySlot`;
- `CreatureBreedingData`;
- `CreatureGeneticsData`.

Это только сериализуемые точки расширения. Одежда, генетика и скрещивание не реализованы.

## Автоматическая настройка

При использовании `MonstrologyBootstrap` вручную создавать объекты не требуется. Bootstrap:

1. Добавляет `CreatureCollectionManager` на системный объект.
2. Загружает питомцев из текущего `GameProgress`.
3. Передаёт менеджер в `UIManager`.
4. Создаёт кнопку `ПИТОМЦЫ`, окно `МОИ ПИТОМЦЫ` и диалог первого приручения.

Существующие сцены и `CreatureData` не требуют миграции.

## Ручная настройка

Если Bootstrap не используется:

1. Добавьте `CreatureCollectionManager` на постоянный системный GameObject.
2. После `GameManager.Initialize(content)` вызовите:

```csharp
petCollection.Initialize(gameManager);
```

3. Передайте менеджер последним параметром в `UIManager.Initialize`.
4. Создайте панель и добавьте `PetsPanel`.
5. Вызовите:

```csharp
petsPanel.Initialize(gameManager, petCollection, contentTransform);
```

## Приручение

При первом открытии вида через `ExplorationSystem`:

1. `GameManager.AddCreature` открывает вид в энциклопедии и сохраняет прежний прогресс.
2. `ExplorationResult.firstSpeciesDiscovery` сообщает UI, что встреча первая.
3. UI показывает `PetAdoptionDialog`.
4. При ответе «Да» вызывается `CreatureCollectionManager.AddPet`.
5. При ответе «Нет» энциклопедия остаётся открытой, но экземпляр питомца не создаётся.

Новые виды, полученные мутацией, продолжают работать с энциклопедией, но не открывают диалог поимки.

## Сохранение

Питомцы добавлены в существующий `GameProgress`:

```text
GameProgress.pets : List<CreatureInstance>
```

Ключ `PlayerPrefs` остаётся `Monstrology.Progress.v1`. Формат расширен до `version = 2`, поэтому старые сохранения продолжают загружаться. Для старого сохранения список питомцев создаётся пустым.

Сохраняются:

- `uniqueId` и `speciesId`;
- собственное имя;
- уровень и текущий опыт;
- индивидуальная редкость;
- дата получения и возраст;
- характер;
- любимчик;
- пустые структуры будущих аксессуаров, генетики и скрещивания.

Дата хранится в UTC ISO-формате. `ageInDays` пересчитывается при загрузке и открытии коллекции.

## Опыт и уровень

Все имеющиеся питомцы получают:

- `5 XP` за исследование;
- `15 XP` за найденное существо;
- `40 XP` за первое открытие биома.

Формула следующего уровня:

```text
100 + (level - 1) * 50
```

Опыт сверх порога переносится на следующий уровень.

## API коллекции

Основные методы:

```csharp
AddPet(speciesId, customName)
RemovePet(uniqueId)
GetPetById(uniqueId)
GetAllPets()
SetFavorite(uniqueId)
RenamePet(uniqueId, customName)
AddExperienceToAll(amount)
```

`SetFavorite` снимает флаг со всех остальных питомцев, поэтому любимчик может быть только один.

## Совместимость

Не изменены:

- `CreatureData` и authored assets видов;
- логика открытия энциклопедии;
- следы и бонус редкости;
- предметы и мутации;
- квестовые счётчики;
- world pickups;
- WebGL/Yandex Games bridge.

Питомцы являются дополнительным слоем поверх существующей системы видов.
